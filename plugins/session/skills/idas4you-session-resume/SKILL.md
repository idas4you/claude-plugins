# 이어받기

지난 세션이 남긴 정리 파일을 읽어 **지금도 맞는지 확인한 뒤** 보여 준다. 정리는 쓴 순간부터 낡는다 — 그 뒤에 커밋이 쌓였을 수 있고, 남은 일이 이미 끝났을 수 있다. 그래서 정리에 적힌 것을 그대로 옮기지 않고 실제 상태와 대조한다.

## 찾기

1. 저장소 이름과 경로를 정한다. 본 저장소 기준이다 — 워크트리 안이어도 `git rev-parse --path-format=absolute --git-common-dir`의 부모 디렉터리를 쓴다. git 저장소가 아니면 작업 디렉터리.
2. `~/.claude/session-notes/<저장소 이름>/`의 파일을 읽는다(사용자 개인 안내에 다른 위치가 있으면 그것). 디렉터리가 없거나 비었으면 "남긴 정리가 없습니다 — 세션을 끝낼 때 `/idas4you-session-summary`를 쓰면 다음부터 이어받을 수 있습니다"라고 말하고 끝낸다.
3. 후보를 고른다.
   - 머리의 `status`가 `open`이고 `repo`가 이 저장소의 경로와 같은 것(이름만 같은 다른 저장소의 정리를 걸러 낸다).
   - 인자로 주제를 받았으면 `title`과 본문에서 그 주제에 맞는 것만. 맞는 것이 없으면 없다고 말하고 `open`인 것을 목록으로 보인다.
   - 최신 것부터. 자세히 대조하는 것은 가장 최근(또는 주제에 맞는) **하나**이고, 나머지는 목록으로만 보인다.
4. `open`인 것이 없으면 가장 최근의 `closed` 정리 하나를 "지난 세션은 남은 일 없이 끝났습니다"와 함께 제목·시각만 보인다.

## 대조 — 정리에 적힌 것이 지금도 맞는가

고른 정리 하나에 대해 읽기 전용 명령으로 본다. 먼저 `git fetch --prune`.

| 볼 것 | 어떻게 |
|---|---|
| 정리 뒤에 쌓인 것 | `git log --since="<정리의 time>" --oneline --all` — 그 뒤의 커밋이 남은 일을 이미 끝냈는가 |
| 적힌 커밋 | `git cat-file -e <해시>` — 있는가, 지금 어느 브랜치에 들어 있는가 |
| 적힌 브랜치 | 아직 있는가, 머지됐는가, push됐는가(`ahead`·`behind`) |
| 커밋하지 않았다고 적힌 변경 | 그 워크트리에 아직 있는가(`git status --short`). 워크트리가 사라졌으면 그렇다고 적는다 |
| 적힌 파일 | 아직 있는가, 정리 뒤에 바뀌었는가(`git log --since=... -- <경로>`) |
| 지시서(`doc:` 줄) | 지시서의 tasks.md 체크리스트와 인덱스의 상태를 읽는다. **지시서 작업은 tasks.md가 기준이다** — 정리의 "남은 일"과 다르면 tasks.md를 따른다 |

"남은 일"의 항목마다 셋 중 하나로 가른다.

- **남음** — 아직 하지 않았다
- **끝남** — 근거(커밋 해시·파일·tasks.md의 체크)와 함께
- **확인하지 못함** — 저장소 밖의 일(배포 확인, 다른 사람의 답)이거나 볼 방법이 없다. 본 것처럼 쓰지 않는다

## 보고

짧게, 이 순서로.

1. **지난 세션** — 정리 시각, 제목, 브랜치. 그때 한 일을 두세 줄로
2. **남은 일** — 표로. 칸은 `항목 | 지금 | 근거`
3. **그 뒤에 달라진 것** — 정리 뒤의 커밋, 사라진 브랜치·워크트리, 바뀐 파일. 없으면 없다고 쓴다
4. **다른 정리** — `open`인 나머지를 시각·제목으로 한 줄씩. 보려면 `/idas4you-session-resume <주제>`
5. **추천** — 남은 것 중 무엇부터 할지 한 줄로 대고 묻는다("`<항목>`부터 할까요?"). 지시서 작업이면 지시서 경로와 함께 그 지시서를 구현하는 스킬(`/idas4you-doc-impl <지시서 디렉터리>`)을 가리킨다. **답을 받기 전에는 시작하지 않는다.**

## 정리 파일 닫기

- 남은 일이 **모두 `끝남`**으로 확인되면 그 파일 머리의 `status`를 `closed`로 바꾸고 `closed: <실제 시각> — <이유>` 줄을 더한다. 시각은 `date '+%Y-%m-%d %H:%M'`로 읽는다. 보고에 닫았다고 알린다.
- 사용자가 "그건 안 한다"고 한 정리도 같은 방식으로 닫고, 이유에 그렇게 적는다.
- 일부만 끝났으면 `open`으로 두고, 머리에 `resumed: <실제 시각>` 줄을 더한다(여러 번 이어받으면 여러 줄).
- `확인하지 못함`이 남아 있으면 닫지 않는다.
- **본문은 고치지 않는다.** 그때의 기록이다. 바꾸는 것은 머리의 `status`·`closed`·`resumed` 줄뿐이다.
- 파일은 지우지 않는다. 사용자가 지우라고 한 것만 지운다.

## 하지 않는 일

- 묻지 않고 작업 시작하기. 이 스킬은 보여 주고 제안하는 데서 끝난다.
- 코드 수정, 커밋, push, 브랜치 삭제.
- 다른 저장소의 정리 읽기(사용자가 그 저장소를 짚어 말했을 때만).
- 정리에 적힌 것을 확인 없이 사실로 옮기기.
- 비밀값을 보고에 옮기기.
