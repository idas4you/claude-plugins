# 검수하지 않은 지시서 모두 검수

검수하지 않은 지시서를 모아 `/idas4you-doc-check`의 기준으로 하나씩 검수하고, 끝에 한 번 보고한다. **도중에 사용자에게 묻지 않는다** — 자리를 비운 사이에 끝까지 돌 수 있게 하려는 것이다.

검수 기준·판정·구현 모델 추천·검수 이력의 규칙은 `/idas4you-doc-check`에 있고 여기에 다시 적지 않는다. 이 스킬이 정하는 것은 **무엇을 고르는가, 어떻게 나눠 돌리는가, 묻는 대신 무엇을 남기는가**다.

## 대상 고르기

1. 인덱스를 읽는다. 위치는 저장소 안내 파일(`CLAUDE.md`, `AGENTS.md`)과 사용자 개인 안내에 적힌 곳, 없으면 `docs/work/README.md`. 인덱스에 빠진 지시서 디렉터리가 있을 수 있으니 지시서 위치의 디렉터리도 훑는다.
2. 다음을 모두 채우는 것이 대상이다.
   - 상태가 `완료`·`중단`·`대체됨`이 아니다
   - tasks.md에 `## 검수 이력` 표가 없거나 표에 줄이 없다(저장소 템플릿에 검수 기록 자리가 따로 있으면 그것으로 본다)
3. 인자로 말을 받았으면 제목·경로가 그 말에 맞는 것만 남긴다.
4. 대상이 아닌 것 가운데 **검수한 뒤에 지시서가 바뀐 것**(`git log --since="<마지막 검수 일시>" -- <지시서 디렉터리>`에 검수 커밋 말고 다른 커밋이 있다)은 검수하지 않고, 보고에 "검수 뒤 바뀜"으로 이름만 올린다. 사용자가 "바뀐 것도"라고 했으면 대상에 넣는다.
5. 대상이 없으면 "검수하지 않은 지시서가 없습니다"라고 말하고 끝낸다(4의 목록이 있으면 함께 보인다).

시작할 때 대상 목록을 우선순위 순으로 한 번 보이고(인덱스의 `요약` 칸과 함께 — 비었으면 비운 채로 둔다. 목록을 보이려고 design.md를 미리 읽지 않는다), 답을 기다리지 않고 바로 시작한다.

## 돌리기

지시서 하나의 검수는 **하위 에이전트 하나**에 맡긴다(Agent 도구, `model: fable`). 지시서마다 새 맥락에서 보게 하려는 것이다 — 앞 지시서를 읽은 기억이 다음 검수에 섞이지 않는다.

- 한 번에 셋까지 함께 돌린다. 대상이 더 많으면 우선순위 순으로 셋씩.
- 하위 에이전트는 이 대화를 모른다. 지시문에 다음을 넣는다.
  - 지시서 디렉터리의 절대 경로, 인덱스 파일의 경로, 읽어야 할 안내 파일
  - "Skill 도구로 `idas4you-doc-check`를 이 지시서 디렉터리를 인자로 불러 그 절차대로 검수한다"
  - 아래 "묻지 않는다"의 규칙 전부
  - **자기 지시서 디렉터리 안의 파일만 고친다.** 인덱스와 다른 지시서는 고치지 않는다. 커밋·push도 하지 않는다 — 여럿이 함께 돌아 같은 파일을 건드리면 서로 덮어쓴다
  - 돌려줄 것: 판정, 구현 모델 권장과 이유, 다시 판단한 우선순위·선행 지시서와 이유(인덱스에 적을 값), 인덱스 `요약` 칸에 적을 한 줄(끝나면 무엇이 달라지는지, 40자 안쪽), 바로 고친 것, "미결 질문"에 올린 것(구현을 막는 것과 막지 않는 것을 나눠서), 확인하지 못한 것
- 지시서가 연결된 ADR을 고쳐야 하는데 두 대상이 같은 ADR을 가리키면, 그 둘은 함께 돌리지 않고 차례로 돌린다.
- Agent 도구가 없으면 이 세션이 하나씩 차례로 검수한다. 지시서마다 파일을 처음부터 다시 읽는다.
- 하위 에이전트가 실패하거나 결과 없이 끝나면 한 번 다시 맡긴다. 또 실패하면 그 지시서는 "검수하지 못함"으로 보고하고 나머지를 계속한다. 검수 이력 줄은 검수가 끝난 지시서에만 남는다.

### 돌아온 뒤 — 이 세션이 한다

1. **결과를 그대로 믿지 않는다.** 지시서마다 tasks.md를 열어 검수 이력에 줄이 하나 늘었는지, 머리 표의 `구현 모델 권장`이 돌려준 값과 같은지, 돌려준 미결이 실제로 "미결 질문"에 적혔는지 본다. 빠졌으면 채운다(일시는 `date "+%Y-%m-%d %H:%M"`로 읽는다).
2. **인덱스를 한 번에 고친다.** 돌려받은 요약·우선순위·선행 지시서를 인덱스에 옮긴다. `/idas4you-doc-check`의 규칙 그대로다 — `(사용자 지정)` 값은 고치지 않고, 바꾼 값에는 이유와 "(검수 YYYY-MM-DD)"를 붙인다. **"막고 있으면 올린다"는 모든 결과를 모은 뒤 여기서 한 번 더 본다**(하나씩 볼 때는 다른 지시서의 새 값을 모른다).
3. 선행 지시서의 고리가 있으면 고치지 않고 보고한다.
4. 저장소 관행대로 한 번에 커밋·push한다(문서 커밋을 기본 브랜치에 해도 되는 저장소만). 커밋 작성자는 사용자 안내가 정한 이름을 쓴다.

## 묻지 않는다 — 대신 지시서에 남긴다

`/idas4you-doc-check`가 보고로만 알리던 "결정이 필요한 것"을, 이 스킬에서는 **지시서의 "미결 질문"에 적어 둔다.** 구현 세션이 볼 수 있는 것은 파일뿐이기 때문이다.

| 찾은 것 | 처리 |
|---|---|
| 사실 오류, 문서 간 불일치 | `/idas4you-doc-check`와 같다 — 바로 고친다 |
| 설계 결함 | 고치지 않는다. "미결 질문"에 근거(파일:행)·고칠 방향·**권장안**과 함께 올리고 `구현을 막음`이라고 표시한다 |
| 결정을 바꾸는 제안(더 단순한 규칙, 범위 축소) | 고치지 않는다. "미결 질문"에 권장안과 함께 올리고 `구현을 막지 않음`이라고 표시한다 |
| `(사용자 지정)` 우선순위와 판단이 다름 | 고치지 않는다. 끝 보고의 "결정이 필요한 것"에만 적는다(지시서가 아니라 인덱스의 일이다) |

- 미결 항목마다 끝에 "(검수 YYYY-MM-DD)"를 붙여, 사용자가 쓴 미결과 검수가 올린 미결을 가를 수 있게 한다.
- 권장안을 댈 수 없으면 왜 댈 수 없는지(무엇을 알아야 하는지) 적는다.
- 판정은 그대로 낸다. `구현을 막음`인 미결이 남았으면 `고친 뒤 구현`이다 — 묻지 않는다고 판정을 올려 주지 않는다.
- **이 미결은 `/idas4you-doc-impl`이 푼다.** 그 스킬은 구현을 시작하기 전에 지시서의 미결 질문을 읽어, 구현을 막거나 지금 단계에 영향을 주는 것을 사용자에게 묻는다.

## 보고

끝나면 한 번, 짧게.

1. **한눈에** — 표 하나. 칸은 `지시서 | 무엇을(한 줄) | 판정 | 구현 모델 권장 | 우선순위 | 고친 것 | 미결(막음/막지 않음)`. 우선순위가 바뀌었으면 `중 → 상`처럼 적는다
2. **결정이 필요한 것** — 지시서별로 `구현을 막음`인 미결을 권장안과 함께. 막지 않는 것은 건수만
3. **검수하지 못한 것 · 확인하지 못한 것** — 있으면
4. **검수 뒤 바뀐 지시서** — 있으면 이름과 `/idas4you-doc-check <지시서 디렉터리>`
5. **다음 걸음 추천** — 한 줄. `구현 가능`인 것이 있으면 그중 우선순위가 가장 높은 것을 `/idas4you-doc-impl <지시서 디렉터리>`로, 고르려면 `/idas4you-doc-impl-list`. 모두 `고친 뒤 구현`·`다시 쓰기`면 무엇부터 정해야 하는지

지시서별 자세한 문제 목록은 보고에 다 옮기지 않는다. 각 지시서의 수정 이력·미결 질문·검수 이력에 있다.

## 하지 않는 일

- 도중에 묻기. 대상이 많아도, 설계 결함을 찾아도 묻지 않고 적어 둔다.
- 이미 검수한 지시서를 다시 검수하기(사용자가 "바뀐 것도"·"전부 다시"라고 했을 때만).
- 코드 수정, 브랜치 생성, 배포, 시험 실행, 구현 시작.
- 설계 결정 바꾸기. 권장안은 적지만 고르는 것은 사용자다.
- 지시서 상태를 `완료`·`중단`으로 바꾸기.
- 비밀값을 보고나 지시서에 옮기기.
