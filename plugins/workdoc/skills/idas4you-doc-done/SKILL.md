# 작업지시서 닫기

이 스킬은 `/idas4you-doc-impl`이 구현한 지시서를 **닫는다**. 닫는다는 것은 문서의 상태를 실제와 맞추는 일이다 — 인덱스의 상태와 `선행 지시서` 칸이 맞아야 `/idas4you-doc-impl`이 다음 지시서를 제대로 고른다.

이 스킬을 부른 것이 "완료라고 한다"는 사용자의 말이다. 다만 **확인에서 빠진 것이 나오면 닫지 않고 보고한다.**

## 시작

1. 인자를 읽는다.
   - `<지시서 디렉터리>` — `완료`로 닫는다.
   - `<지시서 디렉터리> 중단` — `중단`으로 닫는다. 이유가 말에 없으면 묻는다.
   - `<지시서 디렉터리> 대체됨 <새 지시서>` — `대체됨`으로 닫는다. 새 지시서가 없으면 묻는다.
   - 인자가 없으면 인덱스에서 상태가 `진행 중`인 것을 찾는다. 하나면 그것을 "이 지시서를 닫을까요?"라고 묻고, 여럿이면 우선순위가 높은 것부터 늘어놓고 묻는다.
2. 그 지시서의 design.md·tasks.md(있으면 plan.md·연결된 ADR)와 인덱스를 읽는다.
3. 저장소 안내 파일(`CLAUDE.md`, `AGENTS.md`, `docs/README.md`)과 사용자 개인 안내를 읽어 다음을 정한다: 상태 이름(기본 `완료`·`중단`·`대체됨`), ADR 상태 이름, 머지 대상 브랜치, 끝난 지시서를 옮기는 규칙이 있는지, 문서 커밋을 기본 브랜치에 해도 되는지, 커밋 작성자.
4. 이미 `완료`·`중단`·`대체됨`이면 닫지 않고 그렇다고 말한다. 인덱스만 어긋나 있으면 인덱스를 맞춘다.

## 확인 — `완료`로 닫기 전에

하나씩 실제로 본다. 지시서에 체크돼 있다는 것만으로 넘어가지 않는다.

| 볼 것 | 어떻게 |
|---|---|
| 체크리스트 | tasks.md에 체크되지 않은 항목. "완료 처리" 단계의 항목은 이 스킬이 하는 일이므로 뺀다 |
| 검증 표 | 결과·일자 칸이 빈 줄, 결과가 실패인 줄 |
| 머지 | tasks.md에 적힌 기능 브랜치가 머지 대상에 들어갔는가. `git fetch` 뒤 `git branch -r --merged <대상>`으로 본다. 여러 레포에 걸치면 레포마다. 스쿼시 머지는 이것으로 보이지 않는다 — `gh pr list --state merged --head <브랜치>`로 보거나, 확인할 수 없으면 "확인하지 못함"으로 적는다 |
| 배포·확인 | 지시서에 배포·운영 확인 단계가 있으면 그 결과가 적혀 있는가 |
| 미결 질문 | design.md "미결 질문"에 답이 없는 것 |
| 보고서 | 지시서가 측정 보고서를 쓰기로 했으면 그 파일이 있고 인덱스에 올라 있는가 |

- **빠진 것이 없으면** 바로 닫는다.
- **빠진 것이 있으면 닫지 않는다.** 빠진 것을 지시서의 자리와 함께 목록으로 보고하고, 무엇을 하면 닫을 수 있는지 적는다(구현이 남았으면 `/idas4you-doc-impl <지시서 디렉터리>`).
- 사용자가 빠진 것을 보고도 "그래도 닫아"라고 하면 닫는다. 닫으면서 빠진 것을 수정 이력에 그대로 적는다("검증 표 3번 미실행인 채 완료 처리 — 사용자 결정").
- 체크리스트의 빈 칸이 사실은 끝난 일이면(커밋·출력으로 확인됨) 체크하고 근거를 옆에 적는다. 확인되지 않으면 체크하지 않는다.

`중단`·`대체됨`은 이 확인을 하지 않는다. 대신 머지되지 않은 기능 브랜치와 이미 머지된 부분 변경이 있는지 보고 보고에 적는다.

## 닫기

1. **지시서** — design.md·plan.md·tasks.md 머리의 상태를 닫는 상태와 오늘 날짜로 바꾼다. 수정 이력에 한 줄(`완료 처리(idas4you-doc-done)`, `중단`이면 이유, `대체됨`이면 새 지시서 링크). tasks.md "완료 처리" 단계의 항목 중 이 스킬이 한 것을 체크한다.
2. **인덱스** — 이 지시서의 상태를 바꾸고 `선행 지시서` 칸을 `—`로 한다. `우선순위` 칸은 기록으로 그대로 둔다.
3. **막혀 있던 지시서** — 다른 지시서의 `선행 지시서` 칸에 이 지시서가 있으면:
   - `완료`: 그 칸에서 이 지시서를 지운다. 선행이 모두 사라진 지시서가 "풀린 지시서"다.
   - `대체됨`: 이 지시서를 새 지시서로 바꿔 적는다.
   - `중단`: 지우지 않는다. 그 지시서는 전제가 사라졌을 수 있다 — 보고의 "결정이 필요한 것"에 올린다.
   - 다른 지시서의 우선순위 값은 고치지 않는다(다시 판단하는 것은 `/idas4you-doc-check`다).
4. **ADR** — 이 지시서로 만든 ADR의 상태를 저장소 관행대로 바꾼다(`완료`면 `제안` → `승인`, `중단`이면 `기각` 또는 관행의 이름). 이 ADR이 대체한 옛 ADR의 상태가 `대체됨`으로 돼 있는지 보고, 아니면 맞춘다. ADR 인덱스도 맞춘다.
5. 저장소 안내에 끝난 지시서를 옮기는 규칙이 있으면 따르고, 옮긴 뒤 인덱스와 다른 문서의 링크를 고친다.
6. 저장소 관행대로 커밋·push한다(문서 커밋을 기본 브랜치에 해도 되는 저장소만). 커밋 작성자는 사용자 안내가 정한 이름을 쓴다.

## 보고

사용자에게 이 순서로, 짧게.

1. **닫은 것** — 지시서와 상태 한 줄. 닫지 않았으면 "닫지 않음"과 빠진 것 목록
2. **풀린 지시서** — 이 지시서가 끝나 시작할 수 있게 된 것. 없으면 없다고 쓴다
3. **결정이 필요한 것** — `중단`된 지시서에 기대던 지시서, 머지되지 않은 채 남은 브랜치, 확인하지 못한 것
4. **다음 걸음 추천** — 마지막 줄에 문장 하나. 인덱스에서 끝나지 않았고 선행이 없는 것 중 우선순위가 가장 높은 지시서를 대고, 사용자가 그대로 칠 수 있게 명령을 온전히 적는다("다음은 `<지시서>`(상)입니다. `/idas4you-doc-impl <지시서 디렉터리>`로 구현하는 것을 추천합니다."). 검수를 거치지 않은 지시서면 `/idas4you-doc-check`를 먼저 추천한다. 남은 지시서가 없으면 없다고 쓴다. 직접 시작하지는 않는다.
5. 머지가 확인된 기능 브랜치가 남아 있으면 **지울지 묻는다.** 그러라고 한 뒤에만 지운다(로컬·원격 따로 말한다). 머지가 확인되지 않은 브랜치는 지우자고 하지 않는다.

## 하지 않는 일

- 코드 수정, 머지, 배포, 시험 실행(읽기 전용 명령으로 확인하는 것은 한다).
- 빠진 검증을 대신 돌리거나 결과를 채워 넣기. 숫자는 실제 출력에서만 옮긴다.
- 지시서 내용(설계·결정·범위) 고치기. 바꾸는 것은 상태·수정 이력·체크 표시·인덱스뿐이다.
- 다른 지시서의 우선순위 다시 정하기.
- 사용자가 그러라고 하지 않은 브랜치 삭제.
